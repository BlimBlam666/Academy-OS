# Business Lab

This is a lightweight observation log. It does not change Academy priorities or authorize redesign for commercialization.

## Reusable components discovered

- Phoenix-authoritative operational date selectors for Now / Next, weekly windows, and recurring-event rollover.
- A small attention selector that combines incomplete local tasks with workflow stages that still require human action.
- A manual brief-state model that describes handoffs without implying live agent telemetry.
- Source-linked event cards, checklist patterns, local persistence, and JSON import/export.

## Possible generalized product hypotheses

- Volunteer-led organizations may benefit from a command view that derives a small current workload from existing calendars and local records.
- Human-supervised content workflows may be clearer when “needs attention” is narrower than “not published.”
- Manual external-work states may earn more trust than simulated automation status when no telemetry exists.

## Evidence and observations

- Academy operations already span practices, Sunday events, milestones, content review, checklists, and external reference links.
- Date collisions require explicit precedence and visible ties; a generic “next event” sort is insufficient.
- Convention readiness is important but should not crowd out nearer recurring operations merely because the season is active.
- Existing browser-local records support useful coordination without a backend.

## Unresolved questions

- Which command-view elements remain useful across organizations with different weekly rhythms?
- How often do users need to override derived priority while preserving the authoritative schedule?
- What evidence would justify shared persistence, permissions, or real integration telemetry later?
- Which workflow labels remain understandable outside publishing and volunteer-event contexts?
